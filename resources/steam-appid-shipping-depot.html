Steam release preflight

Why steam_appid.txt should not be in your Shipping depot

A Steam build can look healthy during direct executable testing while still carrying a development override that does not belong in the artifact you upload.

Inspect the final depot source, not only the project directory.

Find every exact steam_appid.txt basename, remove it from Shipping output, fix the step that staged it, rebuild cleanly, and test through the Steam client.

What the file changes

Valve's Steamworks API documentation describes steam_appid.txt as a development aid for supplying an App ID when an application is launched directly. Steam normally provides the App ID when the application is launched through Steam. Valve's release guidance says the override should not ship with a build and should be removed before depot upload.

This creates two different test paths:

  • Direct local launch: a developer may deliberately use the file while testing outside Steam.
  • Release-path launch: the uploaded or installed build should receive its App ID through the intended Steam client workflow.

A successful direct launch does not prove that the depot is clean or that the release-path App ID and Steamworks initialization behave correctly.

1. Search the complete Shipping artifact

Search the staged output or exact depot source—not only the Unreal project, plugin directory, or primary executable folder. Check nested directories, copied client and server outputs, installer payloads, CI artifacts, and manually assembled upload folders.

Record the full relative path of every file whose exact basename is:

steam_appid.txt

Do not stop after the first match. Near matches are separate files and should not be classified as the override merely because their names look similar:

steam_appid.txt.example
steam_appid.txt.bak
my_steam_appid.txt

2. Find the upstream copy step

Deleting the visible file from a final folder is not a durable fix if an earlier step will restore it during the next build. Trace the match back to its source:

  • project or plugin staging rules;
  • post-build and packaging scripts;
  • CI copy or artifact-assembly jobs;
  • stale staging directories; or
  • manual depot preparation.

Remove the release-path copy step while preserving any deliberately separate local development setup.

3. Rebuild from clean staging output

  1. Remove every discovered copy from the staged release artifact and depot source.
  2. Correct the rule, script, job, or manual process that introduced it.
  3. Delete only the known stale staging output for this build.
  4. Rebuild the Shipping target from a clean state.
  5. Search the rebuilt artifact again before upload.

The second search is the gate. It proves that the production path—not a one-time manual cleanup—stopped adding the file.

4. Test the corrected release path

Upload or install the corrected content through the intended Steam workflow, then launch it through the Steam client. Confirm that the intended App ID is supplied and, if the product uses Steamworks, separately verify that API initialization succeeds.

Overlay behavior can be a useful product-specific runtime test, but it is not a substitute for checking the App ID path and Steamworks initialization directly.

5. Preserve a small evidence bundle

  • Unreal Engine version and patch;
  • target platform and Shipping configuration;
  • build or packaging command;
  • staged-file manifest or directory tree;
  • every discovered steam_appid.txt relative path;
  • the upstream process that copied it;
  • clean-rebuild and second-search results; and
  • Steam-client launch and API-initialization results, when applicable.

This turns a one-off cleanup into a repeatable release check and makes a regression easier to localize.

What Engine Release Doctor can check

The current technical core includes an opt-in store.steam rule that checks Shipping-artifact evidence for the exact steam_appid.txt basename. It preserves matching paths, ignores near-match filenames and non-Shipping artifacts, and returns removal, clean-rebuild, depot, and Steam-client retest guidance.

The rule does not delete files, upload a depot, inspect every Unreal setting, or prove complete Steam readiness. The public beta remains an operator-assisted written audit performed by Engine Release Doctor from sanitized evidence, not an automatic repair service or store-approval guarantee.
