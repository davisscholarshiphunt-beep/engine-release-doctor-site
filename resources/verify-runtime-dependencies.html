Staged-artifact verification

Your Unreal plugin is enabled—but did its runtime files reach the build?

An enabled plugin, successful package, or clean compile does not prove that every required runtime file was staged into the artifact you will actually ship.

Check the produced artifact, not only the project setting.

Define the files required by the exact client, server, platform, and configuration, then verify those files in the final output.

Why this failure is easy to miss

A project may work in the editor or on the development machine because SDK files, redistributables, environment variables, or plugin binaries already exist there. The incomplete package fails only on a clean machine, depot, or server.

1. Define the required files

  • Record the platform, architecture, target, and configuration.
  • List native plugins, online subsystems, middleware, and prerequisites.
  • Identify third-party libraries declared by each relevant module.
  • Compare with the last known working artifact when available.

Requirements can change by engine version, plugin version, platform, and client-versus-server target. Avoid relying on a generic copied list.

2. Inspect the final staged output

Search the actual package or server artifact—not the plugin source directory or engine installation. For every required file, record whether it is present in the expected location, present with a suspicious version or architecture, or missing.

3. Compare working and failing manifests

  • Removed or renamed DLLs
  • Files moved to a different directory
  • Client dependencies absent from the server artifact
  • Third-party library version changes
  • Changes to receipts or runtime-dependency declarations

A file-tree diff shows what the pipeline actually produced and is often more useful than changing several project settings at once.

4. Test the exact artifact elsewhere

Run the release on a clean or representative target machine. Preserve the complete missing-module message, loader failure, crash event, or server output. Manually copying one file can isolate a staging problem, but it is not a durable production fix.

5. Preserve an evidence bundle

  • Engine and plugin versions
  • Target and configuration
  • Generated build command and complete packaging log
  • Required-file list and staged-file tree
  • Last working artifact tree
  • Exact runtime failure
  • Results of controlled one-variable tests

A rule worth automating

Engine Release Doctor's current technical foundation includes a manifest-based rule that compares declared required runtime files with staged files and reports a blocking finding when a requirement is absent. This remains an early diagnostic core: it does not yet inspect Unreal projects automatically and is not generally available as a finished product.
