Pre-distribution artifact check

Your Unreal Windows build runs—but can every EXE be signed?

A successful launch does not prove that every executable in the packaged artifact has a valid PE structure or can pass Authenticode signing and verification.

Published July 31, 2026 · Windows release signing preflight

An Unreal Windows package may contain more than one executable: a small root bootstrapper, the main Shipping executable under Binaries/Win64, crash reporters, installers, launchers, and plugin-provided helpers. A reported Unreal Engine 5.5 case showed a root bootstrapper that launched normally but could not be signed because its PE Certificate Table entry pointed beyond the end of the file. The main executable and bootstrapper were separate artifacts, so testing only one would not have caught the release blocker.

1. Inventory every executable that will ship

  • Root bootstrapper executable
  • Main executable under Binaries/Win64
  • Crash reporters and helper programs
  • Installers and launchers
  • Executables introduced by plugins or third-party tools

Record each file's path, size, hash, role, and whether it is already signed. Do not assume two executables produced by the same package have the same binary structure or signing state.

2. Separate four different checks

  • Does the executable launch?
  • Is its PE structure valid?
  • Can it be signed and timestamped?
  • Does signature verification succeed afterward?

A file can pass the first check and fail the other three. Treat each result as separate evidence.

3. Test copies of the exact final artifact

Use copies of the files produced by the real release pipeline—not an editor executable, an earlier build, or a manually reconstructed folder. Preserve the complete SignTool output, including the executable path, Windows SDK version, digest algorithm, timestamp method, exit code, and full error text.

Never include certificate passwords, private keys, hardware-token PINs, or signing-service credentials in a diagnostic bundle.

4. Inspect the bootstrapper separately

When signing fails, compare the root bootstrapper and main Shipping executable independently:

  • File size and hash
  • Existing signature state
  • SignTool sign result
  • SignTool verify result
  • Whether the failure follows only one file

5. Validate the PE Certificate Table

Microsoft documents that the Certificate Table entry identifies the file offset and size of the attribute certificate table. For an unsigned executable, the entry should not falsely point to certificate data outside the file. If a PE inspection tool shows an address or size beyond the file boundary, preserve that finding as evidence of an artifact-structure problem rather than assuming the certificate itself is defective.

6. Compare engine and pipeline conditions

  • Exact Unreal Engine version and patch
  • Launcher build or source-built engine
  • Packaging path and generated command
  • Whether a bootstrap executable was generated
  • Resource editing or other post-processing
  • Antivirus, synchronization, or file-locking interference
  • Last engine or artifact version that signed successfully

Change one variable at a time and keep the original failing artifact so that a successful retest produces useful evidence.

7. Do not make ad hoc binary editing the production fix

Clearing or rewriting a malformed header may confirm the diagnosis, but an unreproducible manual patch can conceal the upstream defect, invalidate release records, or create compliance and maintenance risk. Prefer a corrected packaging path, verified engine fix, or reviewed reproducible post-processing step.

8. Verify the complete signed release

  • Verify every executable that will be distributed.
  • Confirm the expected timestamp and digest algorithms.
  • Launch the signed package on a clean or representative machine.
  • Test the actual installer, launcher, depot, or store-delivered path.
  • Preserve file hashes, inventory, signing output, and verification output with the release record.

Evidence bundle

  • Engine version, target, and packaging method
  • Generated command and complete packaging log
  • Final output-file tree
  • Every distributed executable and its role
  • Complete SignTool sign and verify output
  • PE inspection findings
  • Last working artifact comparison
  • Relevant engine, pipeline, or post-processing changes
